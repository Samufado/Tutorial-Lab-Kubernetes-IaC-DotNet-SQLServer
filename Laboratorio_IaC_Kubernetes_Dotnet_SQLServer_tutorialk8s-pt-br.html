API e EF Core

Entidade Produto e dados de entrada

C#CatalogoApi/Models/Produto.cs
using System.ComponentModel.DataAnnotations;

namespace CatalogoApi.Models;

public class Produto
{
    public int Id { get; set; }
    [Required, MaxLength(80)]
    public string Nome { get; set; } = "";
    public decimal Preco { get; set; }
}

public record ProdutoEntrada(string Nome, decimal Preco);

O EF Core usa Id como chave por convenção. O nome tem limite de 80 caracteres. O record ProdutoEntrada representa o JSON que chega na criação e atualização.

Conceito aplicado

Persistência pertence ao banco. O Pod da API pode ser substituído sem perder os produtos já gravados.

API e EF Core

DbContext e mapeamento

C#CatalogoApi/Data/AppDbContext.cs
using CatalogoApi.Models;
using Microsoft.EntityFrameworkCore;

namespace CatalogoApi.Data;

public class AppDbContext(DbContextOptions<AppDbContext> options)
    : DbContext(options)
{
    public DbSet<Produto> Produtos => Set<Produto>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Produto>()
            .Property(p => p.Preco).HasPrecision(18, 2);
    }
}

DbSet<Produto> representa a coleção consultável. HasPrecision(18, 2) define precisão e escala do preço no SQL Server.

Tempo de vida

A API registra o DbContext como serviço scoped. Cada requisição recebe seu contexto. Evite um DbContext Singleton compartilhado por requisições e threads.

API e EF Core

Geração de migrations sem banco local

C#CatalogoApi/Data/AppDbContextFactory.cs
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Design;

namespace CatalogoApi.Data;

// Usada somente pelo comando que gera as migrations.
public class AppDbContextFactory : IDesignTimeDbContextFactory<AppDbContext>
{
    public AppDbContext CreateDbContext(string[] args)
    {
        var options = new DbContextOptionsBuilder<AppDbContext>()
            .UseSqlServer("Server=localhost;Database=Catalogo;" +
                "Integrated Security=true;TrustServerCertificate=true;")
            .Options;
        return new AppDbContext(options);
    }
}

A ferramenta dotnet ef migrations add usa essa fábrica para conhecer o modelo. A conexão acima serve ao design time: gerar a migration não executa consulta nem exige um SQL Server no Windows.

Atenção à diferença

Essa string não é a conexão usada pelos Pods. Em execução, a API recebe servidor e senha por configuração e Secret.

API e EF Core

Configuração de conexão na API

C#CatalogoApi/Program.cs
using CatalogoApi;
using CatalogoApi.Data;
using Microsoft.Data.SqlClient;
using Microsoft.EntityFrameworkCore;

var migrateOnly = args.Contains("--migrate");
var builder = WebApplication.CreateBuilder(
    args.Where(a => a != "--migrate").ToArray());
var config = builder.Configuration;
var connection = new SqlConnectionStringBuilder
{
    DataSource = config["Db:Server"] ?? "sqlserver,1433",
    InitialCatalog = config["Db:Name"] ?? "Catalogo",
    UserID = config["Db:User"] ?? "sa",
    Password = config["Db:Password"]
        ?? throw new InvalidOperationException("Configure Db__Password."),
    Encrypt = true,
    TrustServerCertificate = true, // Apenas para o cluster local didatico.
    ConnectTimeout = 5
}.ConnectionString;

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(connection, sql => sql.EnableRetryOnFailure(3)));
var app = builder.Build();
  • No .NET, Db__Server vira a chave Db:Server.
  • O builder de conexão trata a senha como valor, mesmo que contenha caracteres especiais.
  • TrustServerCertificate=true simplifica o certificado no ambiente local. Em produção, valide o certificado.
  • EnableRetryOnFailure permite novas tentativas em falhas transitórias, sem tornar qualquer operação infalível.

C#CatalogoApi/ProdutosEndpoints.cs
        app.MapGet("/produtos", async (AppDbContext db) =>
            await db.Produtos.AsNoTracking().OrderBy(p => p.Id).ToListAsync());

        app.MapGet("/produtos/{id:int}", async (int id, AppDbContext db) =>
        {
            var produto = await db.Produtos.FindAsync(id);
            return produto is null ? Results.NotFound() : Results.Ok(produto);
        });

        app.MapPost("/produtos", async (ProdutoEntrada entrada, AppDbContext db) =>
        {
            if (Invalido(entrada))
                return Results.BadRequest("Informe nome (1 a 80 caracteres) e preco valido.");
            var produto = new Produto { Nome = entrada.Nome.Trim(), Preco = entrada.Preco };
            db.Produtos.Add(produto);
            await db.SaveChangesAsync();
            return Results.Created($"/produtos/{produto.Id}", produto);

Leia o arquivo completo pelo botão de download. As outras rotas seguem o mesmo padrão: receber o contexto, operar a entidade e chamar SaveChangesAsync quando houver alteração.

API e EF Core

Saúde: processo vivo e aplicação pronta

C#CatalogoApi/Program.cs
});
app.MapGet("/health/live", () => Results.Ok(new { status = "vivo" }));
app.MapGet("/health/ready", async (AppDbContext db, CancellationToken token) =>
{
    using var timeout = CancellationTokenSource.CreateLinkedTokenSource(token);
    timeout.CancelAfter(TimeSpan.FromSeconds(2));
    try
    {
        return await db.Database.CanConnectAsync(timeout.Token)
            ? Results.Ok(new { status = "pronto" })
            : Results.StatusCode(503);

    catch
    {
        return Results.StatusCode(503);
    }
});
app.MapProdutos();
app.Run();
Por que duas rotas?

/health/live responde sem consultar o banco. /health/ready verifica acesso ao banco. Assim, indisponibilidade do SQL retira a prontidão da API sem criar reinícios em cascata pela liveness.

O teste de conexão não verifica todas as regras de negócio. Ele representa a condição de prontidão adotada neste exercício.

API e EF Core

Modo de migração: a mesma imagem, outra tarefa

C#CatalogoApi/Program.cs
if (migrateOnly)
{
    await Migrator.RunAsync(app.Services);
    return;
}
C#CatalogoApi/Migrator.cs
using CatalogoApi.Data;
using Microsoft.EntityFrameworkCore;

namespace CatalogoApi;

public static class Migrator
{
    public static async Task RunAsync(IServiceProvider services)
    {
        for (var tentativa = 1; tentativa <= 24; tentativa++)
        {
            await using var scope = services.CreateAsyncScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            try
            {
                await db.Database.MigrateAsync();
                Console.WriteLine("Migrations aplicadas.");
                return;
            }
            catch (Exception) when (tentativa < 24)
            {
                Console.WriteLine($"Banco ainda indisponivel: tentativa {tentativa}/24.");
                await Task.Delay(TimeSpan.FromSeconds(5));
            }
        }
    }
}

O argumento --migrate aplica migrations e encerra o processo. O Job terá êxito quando esse processo terminar com código zero. As tentativas limitadas toleram a inicialização do banco. Falha persistente deve ser diagnosticada nos logs.

O script exporta a imagem Linux/AMD64 e a importa nos nós locais. Os manifestos usam imagePullPolicy: IfNotPresent, que permite usar a imagem quando ela já está no nó.

PowerShellscripts/Importar-Imagem-Kind.ps1
# Opcional: somente se o Docker Desktop estiver usando o provisionador kind.
# Execute a partir da raiz LabIaCK8s, apos docker build.
$ErrorActionPreference = "Stop"
if ((kubectl config current-context) -ne "docker-desktop") {
    throw "Selecione o contexto docker-desktop antes de continuar."
}
$nodes = (kubectl get nodes -o json | ConvertFrom-Json).items.metadata.name
$containers = @(docker ps --format '{{.Names}}')
$targets = @($nodes | Where-Object { $containers -contains $_ })
if ($targets.Count -eq 0) {
    throw "Nao encontrei nos kind como conteineres. Este passo e apenas para kind."
}
docker image save --platform linux/amd64 --output tutorialk8s-api.tar tutorialk8s-catalogo-api:1.0
if ($LASTEXITCODE -ne 0) { throw "Falha ao exportar a imagem." }
foreach ($node in $targets) {
    docker cp .\tutorialk8s-api.tar "${node}:/tmp/tutorialk8s-api.tar"
    if ($LASTEXITCODE -ne 0) { throw "Falha na copia para $node." }
    docker exec $node ctr --namespace k8s.io images import --all-platforms /tmp/tutorialk8s-api.tar
    if ($LASTEXITCODE -ne 0) { throw "Falha na importacao para $node." }
    docker exec $node rm /tmp/tutorialk8s-api.tar
}
Remove-Item .\tutorialk8s-api.tar

Execute essa rota somente no cluster local kind. Ela requer Docker recente com docker image save --platform. Se aparecer ErrImagePull, examine os eventos antes de mudar tags ou provisionador.

O que acontece?

O Secret fornece a senha ao banco, ao Job e à API. O comando não grava um arquivo com a senha nem a imprime. Kubernetes Secret não equivale, por si só, a um cofre criptografado.

Não use senha real de outro sistema. Neste ambiente didático a API usa sa; em produção, separe as identidades e limite privilégios.

Importante

Aumentar réplicas de um StatefulSet de SQL Server cria instâncias independentes. Isso não configura replicação de dados nem alta disponibilidade.

Infraestrutura

SQL Server: senha, memória e armazenamento

YAMLk8s/02-sqlserver.yaml
        - name: sqlserver
          image: mcr.microsoft.com/mssql/server:2022-latest
          ports:
            - containerPort: 1433
          env:
            - name: ACCEPT_EULA
              value: "Y"
            - name: MSSQL_PID
              value: "Developer"
            - name: MSSQL_MEMORY_LIMIT_MB
              value: "2048"
            - name: MSSQL_SA_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: banco-secrets
                  key: SA_PASSWORD
          resources:
            requests:
              cpu: "500m"
              memory: "2Gi"
            limits:
              cpu: "2"
              memory: "3Gi"
          volumeMounts:
            - name: dados
              mountPath: /var/opt/mssql
          startupProbe:
            tcpSocket:
              port: 1433
            periodSeconds: 5
            failureThreshold: 60
          readinessProbe:
            tcpSocket:
              port: 1433
            periodSeconds: 5
  volumeClaimTemplates:
    - metadata:
        name: dados
      spec:
        accessModes: ["ReadWriteOnce"]
        resources:
          requests:
            storage: 8Gi
  • A edição Developer atende ao uso educacional, sem publicar a porta no Windows.
  • O processo recebe limite interno de memória inferior ao limite do contêiner, deixando margem.
  • fsGroup ajuda a compatibilizar as permissões do volume com o usuário do SQL Server.
  • O PVC de 8 GiB terá nome dados-sqlserver-0. A StorageClass padrão deve provisioná-lo.

A sonda TCP verifica a porta. O Job ainda precisa conseguir autenticar e aplicar SQL; porta aberta sozinha não comprova isso.

                  key: SA_PASSWORD
          resources:
            requests: {cpu: "100m", memory: "128Mi"}
            limits: {cpu: "1", memory: "512Mi"}

O Job usa a mesma imagem da API, mas passa --migrate. ConfigMap e Secret fornecem sua conexão. Ele pode terminar com sucesso, ao contrário do processo HTTP que deve permanecer em execução.

Conceito

A conclusão da migration é uma etapa de implantação. Os Pods de API não alteram o esquema ao iniciar.

Infraestrutura

Aplique e confira a migration

PowerShell
kubectl apply -f .\k8s\03-migration-job.yaml
kubectl -n iac-tutorialk8s wait --for=condition=complete job/db-migrate --timeout=300s
kubectl -n iac-tutorialk8s logs job/db-migrate
kubectl -n iac-tutorialk8s get jobs
Checkpoint

Espere Complete e a mensagem Migrations aplicadas. Só depois prossiga.

Se o Job falhar, verifique os logs, o DNS, a senha, a imagem e a existência da migration. Após corrigir a causa, recrie somente o Job:

PowerShell
kubectl -n iac-tutorialk8s delete job db-migrate
kubectl apply -f .\k8s\03-migration-job.yaml

O histórico do EF Core registra migrations aplicadas. Reexecutar o Job sem novas migrations não deve recriar as tabelas nem apagar seus produtos.

O Deployment declara a imagem e a quantidade de Pods. Os labels do template devem corresponder aos seletores do Deployment e do Service.

Decisão de projeto

A API não grava produtos em arquivos locais. Réplicas diferentes acessam o mesmo banco pelo Service SQL.

Infraestrutura

Sondas e portas da API

YAMLk8s/04-api.yaml
            httpGet: {path: /health/live, port: http}
            periodSeconds: 2
            failureThreshold: 30
          livenessProbe:
            httpGet: {path: /health/live, port: http}
            periodSeconds: 10
          readinessProbe:
            httpGet: {path: /health/ready, port: http}

            timeoutSeconds: 3

apiVersion: v1
kind: Service

  name: catalogo-api
  namespace: iac-tutorialk8s

  type: ClusterIP
  selector:
    app: catalogo-api
  ports:
    - port: 80
      targetPort: http
  • Startup aguarda o início do servidor.
  • Liveness observa o processo sem depender do banco.
  • Readiness condiciona o tráfego normal do Service ao acesso ao SQL Server.
  • O Service escuta em 80 e encaminha para a porta nomeada http, que corresponde a 8080.
Verificação

Publique a API e abra o acesso local

PowerShell
kubectl apply -f .\k8s\04-api.yaml
kubectl -n iac-tutorialk8s rollout status deployment/catalogo-api --timeout=180s
kubectl -n iac-tutorialk8s get pods,svc
kubectl -n iac-tutorialk8s port-forward service/catalogo-api 8080:80
Terminal A fica aberto

O port-forward ocupa esse terminal. Abra um segundo PowerShell, chamado Terminal B, para fazer as chamadas HTTP.

Acesso: http://localhost:8080. Se a porta 8080 estiver ocupada, use 8081:80 e ajuste a URL dos próximos comandos. Para encerrar o encaminhamento, pressione Ctrl+C.

O port-forward serve ao desenvolvimento. Ele não representa uma publicação de produção nem demonstra todo o balanceamento do Service.

Verificação

Primeiras chamadas HTTP

PowerShell
# Terminal B
$base = "http://localhost:8080"
Invoke-RestMethod "$base/"
Invoke-RestMethod "$base/health/live"
Invoke-RestMethod "$base/health/ready"
Invoke-RestMethod "$base/produtos"
Resultado esperado

A raiz informa versão e nome do Pod. Saúde retorna vivo e pronto. A lista de produtos começa vazia.

Se a readiness responder 503 ou não houver endpoint pronto, confira os logs da API, a senha do Secret e o Job de migration. Running sozinho não prova prontidão.

Verificação

Crie, consulte e altere um produto

PowerShell
$json = @{ nome = "Caderno"; preco = 19.90 } | ConvertTo-Json
$criado = Invoke-RestMethod -Method Post -Uri "$base/produtos" -ContentType "application/json" -Body $json
$criado
Invoke-RestMethod "$base/produtos/$($criado.id)"

$novo = @{ nome = "Caderno universitario"; preco = 24.90 } | ConvertTo-Json
Invoke-RestMethod -Method Put -Uri "$base/produtos/$($criado.id)" -ContentType "application/json" -Body $novo
Invoke-RestMethod "$base/produtos"

Você deve receber um id, consultar o registro e observar o novo nome e preço. Anote o identificador: vamos verificar a persistência antes de excluir o produto.

Validação

Uma entrada com nome vazio ou preço negativo deve retornar 400. O PowerShell sinaliza esse status como erro HTTP; nesse teste o erro é o resultado esperado.

Experimentos

Persistência: substitua o Pod do banco

Mantenha o produto salvo. No Terminal B, execute:

PowerShell
kubectl -n iac-tutorialk8s delete pod sqlserver-0
kubectl -n iac-tutorialk8s get pods,pvc
kubectl -n iac-tutorialk8s wait --for=condition=Ready pod/sqlserver-0 --timeout=300s
kubectl -n iac-tutorialk8s rollout status deployment/catalogo-api --timeout=180s
Invoke-RestMethod "$base/produtos"
Resultado esperado

O StatefulSet recria sqlserver-0, reutilizando dados-sqlserver-0. O produto deve continuar no banco. Durante a interrupção, a API pode perder prontidão e suas chamadas podem falhar.

Se o wait informar NotFound logo após a exclusão, aguarde alguns segundos e repita-o. Depois aguarde a API voltar a Ready e repita a consulta. Você removeu o Pod, não o PVC. Não exclua o namespace durante esse teste.

Atualização e reversão da aplicação

1. Construa a versão 1.1

No CatalogoApi/Program.cs, mude a versão da resposta da raiz de 1.0 para 1.1. Salve e execute o build na raiz LabIaCK8s.

PowerShell
docker build --platform linux/amd64 --provenance=false `
  -f .\CatalogoApi\Dockerfile -t tutorialk8s-catalogo-api:1.1 .

2. Disponibilize a imagem no cluster

  • Rancher Desktop com dockerd (Moby) ou Docker Desktop com Kubeadm. Após o build no motor local, avance para a edição do YAML.
  • Docker Desktop com kind. Confira o provisionador na área Kubernetes. No script do slide 21, substitua tutorialk8s-catalogo-api:1.0 por tutorialk8s-catalogo-api:1.1 no comando docker image save e execute o bloco atualizado na raiz do projeto.

3. Edite o Deployment em k8s/04-api.yaml

Abra o arquivo no VS Code. Localize o documento YAML com kind: Deployment e metadata.name: catalogo-api. Em spec.template.spec.containers, encontre o item name: api. Altere a linha image: desse item para a tag exata usada no build e confira a linha seguinte. Mantenha a indentação e salve com Ctrl+S.

        - name: api
          image: tutorialk8s-catalogo-api:1.1
          imagePullPolicy: IfNotPresent

Use a tag explícita 1.1 para o nó localizar a imagem construída. Se houver um port-forward aberto, encerre-o com Ctrl+C no Terminal A. Na raiz do laboratório, aplique o arquivo salvo e aguarde o rollout.

PowerShell
kubectl apply -f .\k8s\04-api.yaml
kubectl -n iac-tutorialk8s rollout status deployment/catalogo-api --timeout=180s

Após a mensagem successfully rolled out, reabra o encaminhamento com kubectl -n iac-tutorialk8s port-forward service/catalogo-api 8080:80. Em outro PowerShell, execute Invoke-RestMethod http://localhost:8080/ e confira a versão 1.1. Para reverter declarativamente, restaure a imagem 1.0 no YAML e reaplique. Senha e volume

Alterar o Secret não muda automaticamente a senha de um SQL Server já inicializado. Para preservar dados, altere o login adequadamente. Recriar o volume é uma opção apenas para zerar os dados descartáveis desta atividade.

Conclusão

Limpeza com preservação ou exclusão de dados

Para encerrar a aula preservando os dados, encerre o port-forward e reduza as cargas:

O PVC permanece. Para retomar, reaplique o StatefulSet e o Deployment com réplicas maiores que zero, aguarde o banco e confira prontidão.
